# Release 下保留调试符号

这部分是当前工程非常值得知道的一个实践。

## 目标不是“完整 Debug 构建”

当前项目并没有把日常主构建切成传统的 Qt Debug 套件依赖模式。  
相反，它采用的是：

> 以 Release 形态为主，但保留足够的调试信息，让我们仍然能断到代码。

这样做的原因很现实：

- 不想强依赖完整 Qt Debug DLL 套件
- 希望运行环境尽量接近比赛真实形态
- 但又不能失去 C++ 调试能力

## 当前 CMake 已经做了什么

根 `CMakeLists.txt` 里已经明确加入了这些关键选项：

- `/Od`：关闭优化
- `/Zi`：生成调试信息
- `/DEBUG`：链接阶段生成调试信息

同时 `CMakePresets.json` 里主构建预设也是 `Release`。

这意味着当前工程实际上走的是一种“偏 Release 运行形态 + 保留 PDB”的路线。

## 你应该看到什么结果

在 `ZBin/` 目录下，正常情况下你会看到：

- `Medusa.pdb`
- `MedusaCore.pdb`
- `Client.pdb`

这些文件的存在，就是 VS Code / Visual Studio 能正确映射源码断点的重要前提之一。

## 这套做法的直接好处

- 更接近真实运行环境
- 不必为了调试去维护完整 Debug 版 Qt 运行库
- 大多数时候已经足够进行源码级单步

## 你仍然要注意什么

### 1. 优化级别和调试体验不是完全等价概念

即便已经加了 `/Od` / `/Zi`，有些跨模块、内联、模板相关的调试体验仍然可能没有纯 Debug 那么丝滑。

### 2. 要确认调到的是最新二进制

很多“断点飘了”的问题，其实不是符号没开，而是：

- 你改了源码
- 但没有重新编译对应模块
- VS Code 连到的是旧的 exe / dll / pyd

### 3. Python-C++ 混合时还要考虑 `pyd` / `dll` 同步

如果你调的是 Python 顶层，还要确认：

- `CppPackage.pyd`
- `MedusaCore.dll`
- `CppPackage.pyi`

至少前两个已经是最新构建结果。

## 一句话经验

当前项目的调试思路不是“切 Debug 模式再说”，而是：

> 在主 Release 工作流里，尽量保留足够的符号和可单步能力。

这正是它适合比赛工程长期维护的地方。
